FSMac 1.0.3 · user and technical manual

FSMac Manual

FSMac lets a Mac read and write Windows (NTFS) and Linux (ext2, ext3, ext4) disks. Connect one and it appears in Finder, ready to use, and ejects like any other disk.

Install

  1. Copy the app

    Open FSMac-1.0.0.dmg and drag FSMac to Applications.

  2. Open FSMac

    A welcome window appears and a drive icon is added to the menu bar. If macOS says the app can't be opened because it is from an unidentified developer, Control-click FSMac in Applications, choose Open, then confirm. You only need to do this once.

  3. Install the helper

    Click Install Helper. The helper is a small background service that does the actual mounting, for every user of the Mac, including when the menu bar app is closed.

  4. Allow it in System Settings

    macOS asks you to approve it. Go to System Settings › General › Login Items & Extensions and turn on FSMac under Allow in the Background. The welcome window ticks the step off once the helper is running.

  5. Give the helper Full Disk Access

    macOS doesn't let background services read connected disks without Full Disk Access, and it can't ask on their behalf. The first time you connect a disk, the menu bar window shows Allow FSMac to read disks. Click Open Settings: Privacy & Security › Full Disk Access opens, together with a Finder window showing fsmacd. Drag fsmacd into the list and make sure it is turned on. You only do this once.

  6. Connect a disk

    NTFS and ext volumes are mounted automatically, a few seconds after access is granted the first time. They appear in Finder's sidebar and on the desktop, and are listed in the menu bar window.

If the Login Items step fails

Use Install with Password… in the welcome window or in Settings › Helper. It installs the same helper as a classic LaunchDaemon after asking for an administrator password. The command-line equivalent:

sudo /Applications/FSMac.app/Contents/Helpers/fsmac install-helper

To start the menu bar app at login, turn on Open FSMac at login in the welcome window or in Settings › General. The app is optional: the helper mounts disks without it.

Everyday use

Work with the disk in Finder or any app as usual. A few things are worth knowing:

Mounting
Automatic when a disk is connected. Volumes appear at /Volumes/<name>. Two volumes with the same name get Name and Name 1.
Ejecting
Use Finder's eject button, Eject next to the disk in the menu bar window, Disk Utility, or fsmac eject. FSMac checks every step before it says the disk is safe:
  1. each volume is unmounted and confirms that all its data was written and that it was marked clean;
  2. any other volume on the disk is unmounted;
  3. the drive is asked to write its own cache to the disk;
  4. the disk is ejected.
The menu then shows the disk as Safe to unplug until you unplug it. Many USB drives stay connected after an eject until the cable is pulled; for those the card also offers Mount Again. If the disk also holds a volume macOS mounted itself (for example an exFAT partition), unmounting the FSMac volume in Finder leaves the disk attached; eject the disk from Finder as usual.
Files in use
A volume with open files is not unmounted. FSMac tells you which apps hold it, for example The volume is in use by Preview.
Unplugging
Always eject first. If a disk disappears while mounted read-write, FSMac cleans up and shows Disk Not Ejected Properly. NTFS volumes are recovered by ntfs-3g on the next mount and ext volumes are checked with e2fsck automatically.
Finder metadata
Tags, colors, extended attributes, resource forks, the hidden flag and Gatekeeper quarantine are kept, stored natively on the disk, so they survive a trip through Windows or Linux. No ._ files are created.

The menu bar window

Click the drive icon in the menu bar. Volumes are grouped by physical disk, with an Eject button next to each disk's name; while a disk is being ejected, the current step is shown there. Each row shows the volume's name, format, free space and state, with buttons to open it in Finder or mount it, and a ⋯ menu for everything else.

Check, repair, erase

Check Disk

Check looks for problems without changing anything; Repair fixes them. A mounted volume is unmounted for the check and mounted again afterwards. Both need an administrator account.

FormatCheckRepair
ext2/3/4e2fsck -fne2fsck -fy, a complete repair
NTFSntfsfix -nntfsfix -d: fixes common inconsistencies, resets the journal and clears the dirty flag. For deep repairs run chkdsk /f on Windows.

Erase

Creates a new, empty NTFS or ext4 volume. You can erase just the selected volume or the entire disk. Erasing the entire disk creates a GUID partition table with one data partition of type Microsoft Basic Data, which Windows, Linux and macOS all accept. FSMac refuses to erase the startup disk and macOS system partitions. Internal disks can only be erased from the command line, with fsmac format … --force.

Careful

Erasing deletes everything on the volume or disk and cannot be undone.

Names are limited to 32 characters on NTFS and 16 bytes on ext4. New ext4 volumes use e2fsprogs 1.47 defaults (journal, extents, 64-bit, metadata checksums).

Command line

Install fsmac into /usr/local/bin with Settings › Helper › Install Command-Line Tool…, or run it from /Applications/FSMac.app/Contents/Helpers/fsmac. A volume is a device name (disk4s1), a volume name, or a mount point.

$ fsmac list
DEVICE   TYPE  NAME            SIZE                    STATE    MOUNT POINT
disk4s2  NTFS  Windows Backup  412 GB free of 1 TB     mounted  /Volumes/Windows Backup
disk4s3  ext4  linux-home      31 GB free of 512.11 GB mounted  /Volumes/linux-home
CommandWhat it does

fsmac mount <volume> [--read-only]Mount. --remove-hibernation discards Windows' hibernation data and mounts read & write.
fsmac unmount <volume> [--force] [--eject]Unmount; optionally eject the disk afterwards.
fsmac eject <volume|disk> [--force]Unmount everything on the disk and eject it, printing each step. It ends with safe to unplug, or with not ejected: … Not safe to unplug (exit status 1).
fsmac mount <disk>Mount an ejected disk that is still connected, e.g. fsmac mount disk4.
fsmac check <volume> [--repair]Check or repair, printing the tool's output.

fsmac config [<key> <value>]Show the settings, or change one. Keys are listed under Settings.

Examples:

fsmac mount "Windows Backup" --read-only
fsmac check disk4s3 --repair
fsmac format disk5 --type ext4 --label pi-data
fsmac config ntfsMode read-only

NTFS details

File names

NTFS stores names in UTF-16 and Windows rejects a few characters that are fine on a Mac. With Windows-compatible names on, FSMac stores them as characters from Unicode's private-use area. This is the mapping used by macOS's SMB client and Windows' Services for Mac, so Windows shows look-alike characters, and FSMac and macOS's own NTFS driver show the original names.

On the MacStored on disk
" * : <U+F020, U+F021, U+F022, U+F023
> ? \ |U+F024, U+F025, U+F026, U+F027
Control characters U+0001–U+001FU+F001–U+F01F
A trailing space / a trailing periodU+F028 / U+F029

Lookups are case-insensitive, like on Windows, and case-only renames (photo.JPG → photo.jpg) work. Names are normalized to NFC, the form Windows and Linux use.

Attributes and metadata

  • Extended attributes, tags and resource forks are stored as NTFS named streams.
  • The Windows hidden attribute is Finder's hidden flag, and vice versa.
  • The Windows read-only attribute is the owner's write permission.
  • Junctions and symbolic links created on Windows appear as symbolic links.
  • Compressed and sparse files can be read and written. Files encrypted with Windows EFS cannot be read.
  • Windows permissions (ACLs) are not translated; files show the permissions chosen in Settings.

Hibernated Windows and Fast Startup

When Windows hibernates, or shuts down with Fast Startup, it saves its session on the disk and expects to find the disk unchanged. Writing to it then can lose data. FSMac therefore mounts such volumes read-only and says so. You have two options:

  • Start Windows and shut it down fully: hold Shift while choosing Shut Down, or turn off Fast Startup in Windows' power settings.
  • Choose Mount Read & Write (discard Windows hibernation)… in the volume's ⋯ menu. This deletes the saved session, and anything unsaved in it is lost. Windows then starts fresh.

ext2/3/4 details

Ownership and permissions

By default all files appear to belong to the user logged in at the Mac. That user changes with logins and fast user switching. Permissions follow the owner bits stored on disk. New files and folders get the owner and group of their parent folder, so they stay accessible to the right account on Linux. To work with the real Linux owners and permissions instead, turn on Settings › ext4 › Show the Linux owners.

Journals and unclean volumes

A journal left by a Linux system that crashed or was unplugged is replayed when the volume is mounted. With Check unclean ext volumes on, a volume that was not unmounted cleanly is checked with e2fsck -p first, and the menu reports when it was repaired. FSMac writes data in place and flushes it within a few seconds of the last change (immediately when an app syncs a file). It does not use the journal for its own writes, so eject before unplugging.

Volumes mounted read-only

These are mounted read-only, with the reason shown in the menu:

  • The filesystem is marked as having errors. Repair it with Check Disk….
  • It uses features FSMac does not write: case-folding, fs-verity, quota tracking or shared blocks.
  • It has an external journal, or it is a journal device.
  • The disk is write-protected.

Extended attributes and Finder metadata are stored in the user. namespace, so Linux tools like getfattr see them. Inline data, bigalloc, 1 KB blocks, ext2 without a journal and ext3 are all supported for reading and writing.

Limitations

  • No Trash. These volumes behave like network volumes in Finder, which offers to delete items immediately instead of moving them to the Trash.
  • Spotlight does not index them, and Time Machine cannot back up to them.
  • Hard links are preserved, but the extended attributes of a hard-linked file are only visible through one of its names.
  • Apple silicon only. This build is not universal.
  • Not notarized. On a Mac other than the one it was built on, the first launch needs Control-click › Open.
Release status, 1.0.3

Tested on macOS 27 with disk images: every NTFS and ext code path, the helper's lifecycle, and the app. With a real USB drive (NTFS and ext4 partitions), mounting read & write, reading, and ejecting from FSMac, from Finder and with diskutil eject (including Mount Again) have been verified through the installed helper. Writing to a real drive, noticing that an ejected drive was unplugged, the fsmac_ext.fs component that keeps macOS from calling ext disks unreadable, and unplugging a drive without ejecting have not yet been verified on real hardware.

Troubleshooting

Start with fsmac status and the helper's log (fsmac log -f, or Settings › Helper › Show Logs in Finder). Each mounted volume also has its own log, named after the device, for example disk4s2.log.

The menu says the helper is not running

Open Settings › Helper. If it says Waiting for approval, turn FSMac on in System Settings › General › Login Items & Extensions. If it is installed but not responding, click Reinstall. If Login Items registration doesn't work on your Mac, use Install with Password….

The menu says “Allow FSMac to read disks”

The helper doesn't have Full Disk Access yet, so macOS refuses to let it read the disk. Click Open Settings, drag fsmacd into the Full Disk Access list and turn it on. FSMac retries every few seconds and mounts the disk as soon as access is granted. Until then, NTFS volumes are available read-only through macOS's own driver.

A disk doesn't show up

Check that macOS sees it with diskutil list. Run fsmac list: a volume marked ignored or not mounted can be mounted from the menu. If the volume isn't listed at all, it isn't NTFS or ext, or its first sectors are unreadable; the log says which.

A volume was mounted read-only

The reason appears under its name. The usual causes:

  • Windows is hibernated (see NTFS details).
  • The ext volume has errors: use Check Disk… › Repair.
  • The disk is write-protected.
  • The volume's preference is Mount Read-Only.
Eject says the volume is in use

The disk was not ejected and it is not safe to unplug it. Quit or close the apps named in the message, including Terminal windows whose current folder is on the volume, then click Try Again. Eject Anyway… works too, but those apps lose unsaved changes to files on the volume. Spotlight and Quick Look are waited for automatically.

The disk is still listed after ejecting

That is normal for many USB drives: they stay connected until you unplug them. The card says Safe to unplug, so unplug it whenever you like, or click Mount Again to keep using it.

macOS says a Linux disk “was not readable”

This appears when the helper isn't installed, because macOS has no ext driver of its own; click Ignore and install the helper. The helper installs /Library/Filesystems/fsmac_ext.fs so that macOS recognizes ext volumes and leaves them to FSMac. If the message still appears right after installing, restart the Mac once.

“Disk Not Ejected Properly”

The disk disappeared while mounted read-write. Reconnect it: NTFS volumes are recovered on mount, and ext volumes are checked automatically if Check unclean ext volumes is on. To be thorough, run Check Disk… › Repair.

Files show the wrong owner, or “You don't have permission”

On NTFS, check the Windows read-only attribute: it removes write permission. On ext volumes with Show the Linux owners on, files belong to their Linux users; turn it off to present them as yours.

The menu says the helper is from another version

After updating the app, click Update. The old helper unmounts its volumes cleanly, and the one from the new app takes over. Updating from 1.0.0 registers the helper again, so macOS may ask you to allow it in Login Items once more.

How it works

macOS only lets software add filesystem drivers with entitlements Apple grants individually. FSMac therefore serves each volume from a small program on the Mac, and macOS's built-in NFS client mounts it. The traffic stays inside the machine, over the loopback interface.

ComponentRole
fsmacdThe helper, a LaunchDaemon. It watches Disk Arbitration, identifies NTFS and ext volumes, keeps macOS's read-only NTFS driver off volumes FSMac mounts, starts a worker per volume and mounts it. It also handles unmounts and ejects, including ones requested by Finder or Disk Utility, and cleans up after unplugged disks and failed workers.
fsmac-workerOpens the device and mounts it with ntfs-3g or libext2fs. It serves it as an NFSv3 server and translates extended attributes between virtual AppleDouble (._) files and native attributes on disk.
fsmac_ext.fsA Disk Arbitration filesystem bundle with a probe tool that only reads the ext superblock. It makes macOS recognize ext volumes and leave them to FSMac.
fsmac-probeIdentifies volumes and reads labels, UUIDs and clean state.
FSMac.app, fsmacThe menu bar app and the command line. Both talk to the helper.
Bundled toolsmkntfs, ntfsfix, ntfslabel (ntfs-3g); mke2fs, e2fsck, tune2fs (e2fsprogs).

Security

  • Workers accept connections only from 127.0.0.1 and only from privileged ports, so only the kernel's NFS client can reach them. Once a worker has opened the device and its socket, it gives up root and runs as nobody, because it parses untrusted on-disk data.
  • The helper's socket is open to local users, and requests are authorized per user. Mounting, unmounting and ejecting FSMac volumes are open to everyone, as in Finder. Changing settings, checking and erasing need an administrator. Overriding a volume's preference, force unmounting and discarding hibernation data need an administrator or the user at the Mac. Ejects are limited to disks that hold FSMac volumes.

Mount options

Volumes are mounted from 127.0.0.1:/fsmac/<device>/<name> with:

vers=3,tcp,hard,intr,timeo=600,retrans=10,deadtimeout=0,locallocks,nfc,
rsize=1048576,wsize=1048576,readahead=32,nordirplus,nodev,nosuid,mutejukebox,resvport

Hard mounts keep a long operation from turning into an I/O error; if a worker fails, the helper force-unmounts instead. nordirplus keeps the client from answering lookups of the virtual ._ files from a cached listing. A duplicate-request cache makes retransmitted creates, renames and deletes safe. When a worker exits, its status says why:

Worker exit statusMeaning
0Stopped cleanly; everything written and the volume marked clean.
1Failed after mounting.
2Bad arguments.
3The filesystem could not be mounted.
4The device stopped responding or disappeared.

Build from source

You need macOS 14 or later, Xcode or the Command Line Tools, and autoconf, automake, libtool and pkg-config (for example from Homebrew).

make            # libraries, engine, worker, tools and build/FSMac.app
make test       # the full test suite
make dist       # build/dist/FSMac-<version>.dmg

The app is signed with the first Developer ID Application or Apple Development identity found; set SIGN_IDENTITY to choose one. To develop without installing anything, run the helper unprivileged. It then handles disks you can open yourself, such as attached disk images, and mounts them in FSMacVolumes in your temporary folder ($TMPDIR); the app and CLI connect to it automatically.

build/bin/fsmacd --user-mode
hdiutil attach -imagekey diskimage-class=CRawDiskImage -nomount disk.img

Uninstall

  1. In Settings › Helper, click Uninstall…. FSMac unmounts every volume and removes the helper and /Library/Filesystems/fsmac_ext.fs.

  2. Move FSMac to the Trash. To remove settings and logs as well, delete /Library/Application Support/FSMac and /Library/Logs/FSMac.

If you installed with a password, uninstall with:

sudo /Applications/FSMac.app/Contents/Helpers/fsmac uninstall-helper
